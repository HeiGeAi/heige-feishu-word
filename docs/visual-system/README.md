# 视觉系统与内容契约

本项目面向飞书白色文档页设计。主题适配自 [HeiGe-Design](https://github.com/HeiGeAi/HeiGe-Design)（MIT），通过主辅双色、八种类别色与对应浅底建立视觉层级。正文、KPI 和图表共同服务于同一条阅读主线，白色背景保持连续，颜色帮助读者识别类别和阶段。

## 五条视觉原则

1. **白底一体。** 原生正文与嵌入画板使用连续的白色阅读背景。
2. **标题一次。** 文档标题和精简 metadata 在开头出现，嵌入图不再复制一套封面与标题。
3. **颜色区分类别。** 主辅色组织章节，浓色与浅底对应同一类别；颜色与标签、数值、编号及线型共同表达信息。
4. **图表紧凑。** 将文档内的图示与独立分享图分开排版，避免每个信息块都占一整屏。
5. **结论先行。** 场景模板优先表达判断、影响和下一步，完整数据和流程细节留在可核查的位置。

内容契约允许作者自行安排 `sections` 顺序。编译器不会替作者推断业务结论；自定义文档应明确安排核心判断的位置。

## 六套主题

| ID | 名称 | 主色 `primary` | 图形辅助色 `secondary` | 深色第二类别 `palette[1]` |
| :--- | :--- | :--- | :--- | :--- |
| `atelier-bone` | 海蓝鎏金简报 | `#19466A` | `#D7A236` | `#97600B` |
| `grid-bureau` | 蓝橙经营复盘 | `#2454CE` | `#E57526` | `#B4480B` |
| `nocturne-teal` | 孔雀琥珀简报 | `#006F6B` | `#D99415` | `#995A05` |
| `broadsheet` | 莓果研究速递 | `#B32362` | `#5950C8` | `#493FB3` |
| `moxi-void` | 朱砂石青备忘 | `#B5342C` | `#238FA1` | `#176C83` |
| `soundwave-wrapped` | 洋红明黄提案 | `#B81769` | `#F3CC32` | `#855D00` |

主题 ID 沿用原标识，视觉呈现均已适配白页。`editorial-forest` 继续作为兼容主题，采用森林绿、麦金、湖蓝与浆果色。完整色值以 [`themes.py`](../../src/heige_feishu_word/themes.py) 为准。

每套主题的 `palette` 包含八种浓色，`tints` 包含按相同索引配对的八种浅色。`primary` 等于 `palette[0]`，`surface` 取 `tints[0]`。亮 `secondary` 用于辅助图形强调，第二类别文字和系列采用更深的 `palette[1]`；亮色与可读文字色按用途分开。

原生正文通过 `native`、`native_secondary`、`native_accents` 映射到飞书允许的预设色名，例如 `blue`、`orange`、`green`、`purple`。HEX token 用于 SVG 和 HTML；原生 Docx 保持相近色系，其实际字体、间距和命名颜色由客户端控制，不能承诺与 HEX 色值完全一致。

## 颜色如何服务阅读

白页不等于灰色。纯白的宿主保留正文连续性，主辅双色和类别色用于建立可识别的对应关系，配套浅底让指标与阶段形成清晰区域。本轮调整保留紧凑尺寸、原生文字与文末数据附录，增加的是类别辨识和阅读层级。

- **章节。** 主辅色交替组织标题和标记，帮助读者定位章节，不据此推断章节好坏。
- **KPI。** 首项使用主色实底与白字，其他指标沿前四色的配对关系使用浅底和深色读数。第一项强调作者安排的阅读顺序，不自动表示增长、领先或达标。
- **数据图。** 单系列条形图按类别取色，多系列条形图与折线图按系列取色。同一个系列保持相同颜色，环形、漏斗和完成度条按类别区分。配色不改变值、顺序、零基线或比例。
- **流程。** 阶段采用对应浅底、浓色编号、短顶线与箭头，正文保持深色。步骤先后由编号和连线表达，不能仅按颜色判断当前进度。

成功、提醒或风险的状态语义只来自显式的 `callout.tone` 和 `timeline.status` 字段。普通 KPI、图例或章节里的绿色、红色均不自动带有业绩趋势含义。为支持不同色觉的读者，标签、精确数值、编号标记和折线线型始终保留，识别信息不只依赖颜色。

## 正文与明细

推荐的阅读结构为：原生标题与精简 metadata、核心判断、KPI、正文与图示、行动、数据与流程明细。缺少某种信息时无需为了填满模板强行添加。

原生 XML 将 KPI 数值表、图表数据表和流程全文集中到文末附录。每项明细与原图标题对应，保留完整、可编辑的原生文本。图旁仍有来源和解读，读主线时不必在每张图之后重复阅读整张表。

如果某组 KPI 的合法内容超出画板可读容量，该节直接显示完整原生表格，不生成这组 KPI 的 SVG，也不把同一组指标再次追加到文末。这条回退路径保留原有内容，避免为视觉排版截断业务信息。

离线 `preview.html` 将同样的明细放在图下的 `details` 中，默认收起，按需展开；窄屏图块内部可横向滑动，也可打开原尺寸视图。实际飞书文档使用文末附录，不依赖浏览器的 `details` 展开能力。两种输出保留相同内容，但交互和明细位置不同。

## 输入

支持 Document Body `0.1` 与 `0.2`。`0.2` 在原有六种组件上增加 `prose`、`chart`、`timeline` 和 `comparison`。两版输入均检查支持的字段，未知字段不静默丢弃。省略主题使用 `editorial-forest`，拼错主题明确报错。

`meta.title` 必填；`subtitle`、`audience`、`status`、`reading_time`、`eyebrow`、`disclaimer` 可选。`audience` 为字符串列表，其余字段为文本。`eyebrow` 只呈现文档标记，不触发开篇画板或 HTML 增强版。免责声明由作者提供，编译器不会编造业务状态或数据属性。

| 组件 | 内容字段 | 用途 |
| :--- | :--- | :--- |
| `callout` | `body`，可选 `tone` | 核心判断、风险与提醒 |
| `metrics` | `items`，每项 `label`、`value`、`note` | 关键读数与口径说明，画板适合一至八项 |
| `table` | `columns`、`rows` | 原生明细、行动或比较表 |
| `grid` | `items`，每项 `title`、`body` | 短内容分栏 |
| `whiteboard_workflow` | `steps`，每项 `id`、`title`、`description` | 最多六步的工作流 |
| `actions` | `items`，每项 `owner`、`action`、`due` | 负责人、任务与日期 |
| `prose` | `paragraphs` 字符串列表 | 连续正文 |
| `chart` | `kind`、`labels`、`series`、`source`、`insight`，可选 `unit` | 数据比较、趋势、构成、转化与进度 |
| `timeline` | `items`，每项 `date`、`title`、`body`、`status` | 里程碑和状态 |
| `comparison` | `options`、`criteria`、`recommendation` | 同口径方案比较 |

每节都需要唯一且安全的 `id`，以及 `type` 和 `title`。`callout.tone` 为 `info`、`success`、`warning` 或 `risk`。时间轴最多八项，状态为 `done`、`active`、`planned` 或 `risk`。方案比较包含两至三个选项，每条标准的 `values` 长度必须与 `options` 一致。

### 数据图表

```json
{
  "id": "channel-revenue",
  "type": "chart",
  "title": "渠道收入比较",
  "kind": "bar",
  "labels": ["产品内转化", "内容渠道", "伙伴推荐"],
  "series": [{"name": "收入", "values": [72, 48, 31]}],
  "unit": "万元",
  "source": "合成演示数据，使用前替换",
  "insight": "产品内转化收入最高，下一步需联合成本判断投入。"
}
```

图表最多八个标签。条形图最多两组数据，折线图最多三组，其余单组。折线图至少两点，顺序遵循输入。每组 `values` 与 `labels` 等长，不允许空值、布尔值、NaN 或 Infinity。

`progress` 数值为 0 至 100 的百分比。环形图与漏斗图禁止负数，环形图合计必须大于零，漏斗顺序必须非递增。具体文字容量由字段级错误给出；内容过长时应拆图或明确换算单位，不以截断文字或改写数据掩盖问题。

### 合成数据与真实性

内置预设声明其业务、数值、结论、负责人和日期均为合成示范。复制预设不代表这些信息已被验证。替换数据后需要同时复核指标口径、来源、图表解读和行动承诺。

## 产物与尺寸

每次编译导出原文、XML、SVG、离线预览、主题 token 和含 SHA-256 的清单。默认无网络、无第三方 Python 运行依赖，编译不会创建飞书文档。

| 产物 | 生成条件与内容 |
| :--- | :--- |
| `document.xml` | 总是生成，包含原生正文、嵌入图示和文末明细 |
| `preview.html` | 总是生成，白页预览与可展开明细 |
| `boards/<id>.svg` | 对容量内的 KPI、数据图与工作流生成紧凑嵌入版 |
| `standalone/<chart-id>.svg` | 对每张数据图生成独立分享版，保留标题、来源与解读 |
| `document.enhanced.xml` | 仅第一个 `metrics` 可生成画板时生成，以 HTML 替换该画板 |
| `widgets/overview.html` | 与增强版同时生成，只含第一个 KPI 指标组 |
| `source.body.json`、`theme.json`、`manifest.json` | 保存输入、主题和可核查的产物信息 |

文档内数据图的 SVG 坐标尺寸为 1600×600。KPI 宽度 1600，一至四项时高度 380，五至八项时高度 720。工作流宽度 1600，高度随内容调整。独立分享图为 1600×900，拥有自己的标题和说明。

增强 HTML 只展示第一个指标组的数值、名称和说明，不重复主标题、章节编号、metadata 或页脚。没有 `metrics`，或第一个指标组因视觉容量回退为原生表格时，不生成增强 XML 和 HTML 文件，即使设置了 `eyebrow` 也一样。目标租户和客户端的 HTML 支持仍需验证。

SVG 的坐标尺寸与飞书画板的真实展示高度不是同一项指标。文字重排、节点边界和宿主布局都需要查看实际导入结果，详细说明见 [视觉能力研究](../research/feishu-visual-capabilities.md)。

输出目录仅在上次产物未被修改、没有用户新增文件时允许替换。生成先在临时目录完成；切换到最终目录失败时恢复旧目录。已被用户修改的输出会明确拒绝覆盖。

## 能力与验收边界

- SVG 画板是当前输入的数据快照，修改飞书文末数据表不会重绘图表。数据更新需要重新编译并同步相关内容。
- 原生段落、表格和明细保持编辑能力；SVG 元素的节点转换与视觉保真需要云端验证，不能承诺所有 SVG 特性均可编辑。
- HTML 预览用于查看信息结构与设计意图，不能证明原生 Docx 的字体、间距、实体手机或 PDF 效果。
- 此版本未集成实时 Sheet 数据绑定、原生封面设置、PDF 导出、外部素材导入和自动发布。
- schema 校验、SVG 校验与设计 lint 通过只说明对应规则通过，不能据此宣称好看或阅读体验已经验收。

每次交付应分别记录本地结构检查、浏览器交互、飞书正文回读和画板导出检查。实体手机与 PDF 未执行时应明确记录。具体证据与完成范围见 [验收记录](validation.md)。

明黄只用于图形辅助线与配有深色文字的色面。实际飞书原生黄色标题在白底上偏浅，因此洋红明黄主题的原生章节映射为紫色与蓝色；SVG 和 HTML 保留精确配色。
